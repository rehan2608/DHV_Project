# NIRF Standardized Query Schema Documentation (Phase 3)

This document specifies the Pydantic v2 schemas for standardizing natural-language requests into machine-readable analytical query plans executed by the NIRF Level 3 analytical engine.

---

## Architecture Overview

```text
Natural Language Question
          │
          ▼
   Gemma 4 31B Cloud
          │
          ▼
     QueryParser
          │
          ▼
     QueryPlan (Pydantic Schema)
          │
          ▼
    QueryValidator (Structural, API, Dataset, Comparability, Logic)
          │
          ▼
  Validated Query Plan  ──► (Ready for Phase 4 Execution Router)
```

---

## 1. Top-Level Schema: `QueryPlan`

The `QueryPlan` represents the complete structured request generated by Gemma and passed to the validator.

### Fields

| Field | Type | Description |
|---|---|---|
| `query_id` | `str` | Unique request identifier (e.g. `"qp_4a8b12f0"`). |
| `original_question` | `str` | Exact text of the user's input question. |
| `query_type` | `QueryType` | Analytical category or intent classification (13 supported types). |
| `analytical_intent` | `str` | Concise human-readable explanation of the analytical goal. |
| `confidence_score` | `float` | Estimated confidence in query interpretation ($0.0 \le c \le 1.0$). |
| `operations` | `List[AnalyticalOperation]` | Ordered list of Phase 2 analytical function calls. |
| `conversation_context` | `Optional[ConversationContext]` | Previous turn constraints and inheritance logs. |
| `visualization` | `VisualizationPreference` | User chart, table, or comparison preferences. |
| `clarification_message`| `Optional[str]` | Populated if `query_type == "clarification_required"`. |
| `unsupported_reason` | `Optional[str]` | Populated if `query_type == "unsupported"`. |
| `semantic_retrieval_needed` | `bool` | True if the question asks for NIRF definitions/methodology. |

---

## 2. Query Types (`QueryType`)

The system supports 13 discrete query types:

1. `institution_trend`: Multi-year longitudinal tracking of a single institution.
2. `rank_movement`: Tracking rank gainers/decliners (`start_rank - end_rank`) between two years.
3. `category_performance`: Cohort performance summary, parameter means, and ranked roster.
4. `geographic_analysis`: State representation, institutional counts, top-tier density.
5. `parameter_correlation`: Pairwise Pearson and Spearman correlation matrices.
6. `parameter_relationship`: Bivariate linear regression ($RPC$ vs $TLR$), trendline, quadrants.
7. `multidimensional_performance`: Institutional multi-parameter profiles, percentiles, and gaps.
8. `score_distribution`: Parametric/non-parametric moments, quartiles, IQR, and histogram bins.
9. `rank_transitions`: Transition matrix across ordinal ranking tiers between two editions.
10. `outlier_analysis`: Statistical outliers (Tukey's IQR / Z-score) and domain divergence.
11. `multi_operation`: Queries requiring multiple linked analytical operations.
12. `clarification_required`: Ambiguous entity names or missing critical constraints.
13. `unsupported`: Questions outside NIRF dataset scope.

## 3. Analytical Operation: `AnalyticalOperation`

Each operation maps to a Phase 2 analytical function in `src.analytics.engine.NIRFAnalyticsEngine`.

### Allowed Functions (`AnalyticalFunctionName`)
- `get_institution_trend`
- `get_rank_movement`
- `get_category_performance`
- `get_geographic_analysis`
- `get_parameter_correlation`
- `get_parameter_relationship`
- `get_multidimensional_performance`
- `get_score_distribution`
- `get_rank_transitions`
- `get_outlier_analysis`

### Arguments Specification
- `category` (`Optional[str]`): Validated against 18 standardized NIRF categories.
- `year` (`Optional[int]`): Single assessment edition ($2017 \le y \le 2025$).
- `start_year`, `end_year` (`Optional[int]`): Temporal span for longitudinal functions.
- `states` (`List[str]`): List of target states (supports multiple states for comparison).
- `institution_names` (`List[str]`): Target institutions (supports acronym expansion like "IIT Madras").
- `institution_uids` (`List[str]`): Target standardized UIDs (e.g. `"U-456"`).
- `parameters` (`List[str]`): Target parameters (e.g. `["tlr", "rpc"]`).
- `metric` (`Optional[str]`): Primary measure for distribution/outliers.
- `param_x`, `param_y` (`Optional[str]`): Distinct parameters for bivariate regressions.
- `top_n` (`Optional[int]`): Slice limit for ranked results.
- `applied_defaults` (`Dict[str, Any]`): Explicit audit log of default arguments applied.
- `depends_on` (`Optional[str]`): Operation dependency identifier for sequential workflows.

## 4. Example Standardized JSON Query Plan

### Single-Operation Query
User Question: *"Which engineering colleges in Karnataka have improved their rankings the most since 2020?"*

```json
{
  "query_id": "qp_rank_movement_karnataka_2020_2025",
  "original_question": "Which engineering colleges in Karnataka have improved their rankings the most since 2020?",
  "query_type": "rank_movement",
  "analytical_intent": "Identify engineering institutions in Karnataka with largest rank improvement between 2020 and 2025.",
  "confidence_score": 1.0,
  "operations": [
    {
      "operation_id": "op_1",
      "function_name": "get_rank_movement",
      "description": "Calculate rank improvement (start_rank - end_rank) in Karnataka Engineering.",
      "category": "Engineering",
      "start_year": 2020,
      "end_year": 2025,
      "states": ["Karnataka"],
      "movement_type": "improvement",
      "top_n": 10,
      "applied_defaults": {
        "end_year": 2025
      }
    }
  ],
  "visualization": {
    "chart_requested": true,
    "preferred_chart_type": "horizontal_bar",
    "comparison_requested": true,
    "explanation_requested": false
  },
  "semantic_retrieval_needed": false
}
```

### Multi-Operation Query
User Question: *"Find the top 10 engineering institutions in 2025 with the highest research performance, then examine how research performance relates to teaching performance."*

```json
{
  "query_id": "qp_multi_eng_research_teaching_2025",
  "original_question": "Find the top 10 engineering institutions in 2025 with the highest research performance, then examine how research performance relates to teaching performance.",
  "query_type": "multi_operation",
  "analytical_intent": "Retrieve top research engineering institutions and analyze bivariate relationship between RPC and TLR.",
  "confidence_score": 0.98,
  "operations": [
    {
      "operation_id": "op_1",
      "function_name": "get_category_performance",
      "description": "Get top 10 Engineering institutions in 2025 by research performance.",
      "category": "Engineering",
      "year": 2025,
      "parameters": ["rpc"],
      "top_n": 10
    },
    {
      "operation_id": "op_2",
      "function_name": "get_parameter_relationship",
      "description": "Analyze linear regression and quadrant distribution of RPC vs TLR.",
      "category": "Engineering",
      "year": 2025,
      "param_x": "rpc",
      "param_y": "tlr",
      "depends_on": "op_1"
    }
  ],
  "visualization": {
    "chart_requested": true,
    "preferred_chart_type": "scatter",
    "comparison_requested": true,
    "explanation_requested": true
  }
}
```

## 5. Conversation Context & Follow-Up Representation

The `ConversationContext` object maintains state across conversation turns:

```json
{
  "previous_category": "Engineering",
  "previous_year": 2025,
  "previous_states": ["Karnataka", "Tamil Nadu"],
  "previous_top_n": 5,
  "inherited_fields": ["category", "year"],
  "modified_fields": ["top_n"]
}
```

### Inheritance Rules:
1. **Additive Constraints (States)**: When a user introduces a comparison state (e.g. *"Now compare with Tamil Nadu"*), the query engine appends the state to `states` (`["Karnataka", "Tamil Nadu"]`) rather than overwriting.
2. **Persistent Dimensional Anchors**: `category` and `year` are retained across conversational turns until explicitly superseded by the user.
3. **Slice Modifiers**: Modification of `top_n` (e.g. *"Show only top 5"*) alters the slice size while preserving the multi-state and category filters.
